# DataGuard

iPad의 셀룰러 데이터 사용량을 추정하고, 설정한 기준에 따라 알림과 단축어 자동화를 실행할 수 있는 SwiftUI 앱입니다. 월 데이터 한도에 여유를 두고 사용량을 확인하려는 셀룰러 iPad 사용자를 위한 프로젝트입니다.

## 작동 방식

DataGuard는 기기의 네트워크 카운터에서 셀룰러 사용량 증가분을 읽어 월별 누적량에 더합니다. 앱을 열거나 단축어를 실행할 때 측정하며, 앱이 활성화된 동안에는 30초마다 갱신합니다.

예를 들어 YouTube를 여는 자동화에 DataGuard 단축어를 연결하면, YouTube가 열릴 때 최신 추정 사용량을 확인하고 기준 이상일 경우 Apple의 셀룰러 데이터 끄기 동작을 실행할 수 있습니다. DataGuard 화면을 따로 열 필요는 없습니다.

**백그라운드에서 계속 감시하거나 한도 도달 순간 차단하는 앱은 아닙니다.** YouTube를 계속 시청하는 동안에는 앱 열기 자동화가 반복되지 않습니다. 사용량은 통신사 과금량과 다를 수 있으며, 초과 요금 방지를 보장하지 않습니다.

## 주요 기능

- 월별 추정 사용량, 남은 용량, 사용량 단계 표시
- 월 한도·경고·위험·차단 기준 및 청구 시작일 설정
- 통신사 조회값을 기준으로 현재 사용량 보정
- 측정 공백과 카운터 변경 등 측정 신뢰도 별도 안내
- 경고·위험·차단 기준 도달 시 로컬 알림
- 단축어에서 사용량 조회 및 차단 여부 확인
- 가상 사용량으로 알림과 자동화를 확인하는 테스트 모드
- 네트워크 인터페이스별 수신·송신 카운터 진단

## 준비 사항

- Xcode를 실행할 수 있는 Mac
- Swift 6을 지원하며 대상 iPadOS에 대응하는 Xcode
- iPadOS 17 이상인 셀룰러 모델 iPad
- 기기 설치용 서명에 사용할 Apple 계정

실제 셀룰러 측정과 차단 자동화는 셀룰러 iPad에서 확인해야 합니다. 시뮬레이터는 화면과 테스트 모드 확인용으로 사용할 수 있습니다.

## 빌드 및 설치

```sh
git clone https://github.com/v8k2m4q9/dataguard.git
cd dataguard
open DataGuard.xcodeproj
```

1. iPad를 Mac에 연결하고 기기의 신뢰 및 개발자 모드 설정을 완료합니다.
2. Xcode에서 **TARGETS → DataGuard → Signing & Capabilities**를 엽니다.
3. **Automatically manage signing**을 켜고 **Team**에 본인의 계정을 선택합니다. 저장소의 Team 값은 비어 있습니다.
4. 기본 Bundle Identifier인 `com.local.dataguard`를 사용할 수 없다면 고유한 값으로 변경합니다.
5. 실행 대상으로 연결한 iPad를 선택하고 **Run (⌘R)**으로 빌드·설치합니다.

Xcode에서 플랫폼 지원 구성요소를 요구하면 설치 후 다시 실행합니다. 기기 설치에는 유효한 서명이 필요하며, 서명 유효 기간이 끝나면 다시 빌드·설치해야 할 수 있습니다.

`Package.swift`는 핵심 계산 로직의 테스트용입니다. 앱 설치에는 `DataGuard.xcodeproj`를 사용합니다.

## 처음 설정하기

### 1. 측정할 인터페이스 선택

1. **인터페이스 진단 → 비교 기준 저장**을 누릅니다.
2. Wi-Fi를 끄고 셀룰러로 소량의 데이터를 사용합니다.
3. DataGuard로 돌아와 오른쪽 위 **새로 측정**을 누릅니다.
4. 수신(RX)·송신(TX) 증가량을 비교하고 해당 인터페이스의 **이 인터페이스 사용 (Expert)**을 켭니다.

`pdp_ip`로 시작하는 이름은 셀룰러 후보로 표시됩니다. 기기별로 직접 증가량을 확인해야 하며, 여러 인터페이스를 선택하면 중복 집계될 수 있습니다. Wi-Fi만 사용할 때 선택한 카운터가 불필요하게 증가하지 않는지도 확인합니다.

### 2. 요금제와 사용량 설정

**설정**에서 월 한도와 각 기준을 입력한 뒤 **설정 저장**을 누릅니다.

| 항목 | 기본값 |
|---|---:|
| 월 데이터 한도 | 5.00 GB |
| 경고 | 3.50 GB |
| 위험 경고 | 3.80 GB |
| 차단 권장 기준 | 4.00 GB |
| 안전 여유 | 1.00 GB |
| 청구 시작일 | 매월 1일 |

기준은 `0 < 경고 < 위험 < 차단 < 월 한도` 순서로 설정합니다. 안전 여유는 월 한도와 차단 기준의 차이입니다. 요금제 입력과 단축어의 GB 값은 1 GB = 10억 바이트 기준이며, 화면 표시 단위만 GB/GiB로 선택할 수 있습니다.

이어서 **실제 사용량 보정 → 현재 사용량 (GB)**에 통신사에서 확인한 이번 달 총사용량을 입력하고 **이 값으로 보정**을 누릅니다. 인터페이스 확인 과정에서 사용한 데이터도 포함합니다.

**보정값은 기존 누적량을 대체합니다.** 예를 들어 앱에 0.30 GB가 표시돼 있어도 0.12 GB로 보정하면 총사용량은 0.12 GB가 됩니다. 이후 새로 측정되는 증가분만 더해집니다. 통신사 조회값은 반영이 지연될 수 있습니다.

### 3. 알림 허용

**설정 → 로컬 알림 → 알림 권한 요청 / 확인**에서 권한을 허용합니다. 알림을 거부했다면 iPad의 **설정 → 알림 → DataGuard**에서 변경할 수 있습니다.

## 단축어 자동화 연결

### 검사 단축어 만들기

1. DataGuard를 설치하고 한 번 실행합니다.
2. Apple 단축어 앱에서 새 단축어를 만들고 이름을 `DataGuard 사용량 검사`로 정합니다.
3. DataGuard의 **Should Block Cellular** 동작을 추가합니다.
4. **조건문**을 추가해 앞 동작의 결과가 참인 경우를 지정합니다.
5. 참 분기 안에 Apple의 **셀룰러 데이터 설정 → 끔** 동작을 넣습니다.
6. **그렇지 않은 경우**는 비워두고 편집 화면에서 뒤로 나갑니다. 단축어는 자동 저장됩니다.

```text
Should Block Cellular
조건문: 결과가 참인 경우
    셀룰러 데이터 끔
그렇지 않은 경우
    (동작 없음)
조건문 종료
```

셀룰러 제어는 켜짐/꺼짐을 뒤집는 토글이 아니라 **끔으로 고정**합니다. 해당 동작이 제공되지 않는 기기에서는 알림 표시 동작을 연결하고 직접 셀룰러를 끌 수 있습니다.

### 앱을 열 때 실행하기

1. 단축어 앱의 **자동화 → + → 앱**을 선택합니다.
2. YouTube, Safari 등 검사할 앱을 선택합니다.
3. **열릴 때 → 즉시 실행**으로 설정합니다.
4. **단축어 실행**에 앞서 만든 `DataGuard 사용량 검사`를 지정하고 완료합니다.

등록한 앱을 열 때마다 사용량을 갱신하고 차단 기준 도달 여부를 확인합니다. 실행 간격은 자동화가 호출되는 시점에 따라 달라집니다.

### 제공되는 DataGuard 동작

| 동작 | 반환값 |
|---|---|
| `Should Block Cellular` | 설정한 차단 기준 이상인지 나타내는 참/거짓 |
| `Check Data Limit` | 추정 사용량과 측정 신뢰도에 관한 한국어 안내 |
| `Get Cellular Usage` | 사용량·상태·측정 시각 등을 포함한 상세 결과 |

`Should Block Cellular`는 측정 신뢰도 경고만으로 참을 반환하지 않습니다. 측정·저장 오류가 발생하면 거짓을 반환하므로, 거짓이라는 결과가 정확한 사용량이나 안전한 잔여량을 보증하는 것은 아닙니다. `Get Cellular Usage`에서 오류가 발생하면 해당 단축어 실행이 중단될 수 있습니다.

상세 결과의 주요 속성은 `usedGB`, `remainingToCutoffGB`, `status`, `shouldBlock`, `requiresReview`, `isSimulated`, `sampledAt`, `explanation`입니다.

## 사용량 단계와 측정 신뢰도

대시보드의 `SAFE`, `WARNING`, `CRITICAL`, `BLOCK`은 **기록된 추정 사용량**을 기준으로 표시합니다. `SAFE`는 추정값이 경고 기준 미만이라는 뜻이며, 측정 누락이 없다는 뜻은 아닙니다.

15분 이상 측정 공백, 재부팅·시간 변경, 카운터 감소, 인터페이스 변경 등이 감지되면 **측정 신뢰도 안내**에 사유를 표시합니다. 안내가 생겨도 기존 보정값은 자동으로 0이 되지 않으며, 새로 측정한다고 안내가 곧바로 해제되지는 않습니다.

측정 공백 동안 Wi-Fi만 사용한 것을 알고 있다면 공백 때문에 다시 보정할 필요는 없습니다. 앱이 당시 연결 상태를 확인한 것은 아니므로, 셀룰러 사용량이 불확실하거나 재부팅·카운터 변경이 있었다면 통신사 값과 비교해 보정합니다.

## 청구 기간 변경과 초기화

새 청구 기간은 설정한 시작일과 시간대를 기준으로 계산합니다. 다음 달 첫 측정에서 새 기간을 감지하면 이전 누적량을 초기화합니다. 자정에 앱이 자동 실행되는 방식은 아닙니다.

마지막 측정과 새 기간의 첫 측정 사이 증가량은 두 기간으로 정확히 나눌 수 없어 전부 새 기간에 포함하고 측정 신뢰도 안내를 표시합니다. 시작일이 31일인데 해당 월에 31일이 없으면 말일을 사용합니다.

**Reset now · 0으로 초기화**는 앱 사용량을 0 GB로 보정하는 기능입니다. 통신사 과금량이나 iPad 설정의 통계를 초기화하지 않습니다. 청구일·시간대 설정 변경 시에는 기존 누적량을 보존합니다.

## 테스트 모드와 알림

**설정 → Developer / Test Mode → 가상 사용량 사용**을 켜고 값을 선택한 뒤 **설정 저장**을 누르면 대시보드와 단축어에 가상값을 적용합니다. 연결된 자동화는 실제 셀룰러를 끌 수 있습니다. 검사가 끝나면 테스트 모드를 끄고 다시 저장합니다.

테스트 값은 실제 누적량을 덮어쓰지 않습니다. 테스트 중에는 실제 누적 측정을 멈추고, 종료 후 기존 기준값에서 측정을 이어갑니다. 그 사이의 측정 공백은 별도로 안내될 수 있습니다.

로컬 알림은 **측정 시점에 새로 도달한 가장 높은 단계**를 한 번 알립니다. 기본 설정에서는 3.5 GB 경고, 3.8 GB 위험, 4 GB 차단 기준 알림을 사용합니다. 여러 단계를 한 번에 넘으면 가장 높은 단계만 알립니다. 백그라운드에서 한도 도달 순간 보내는 실시간 알림은 아닙니다.

같은 기간에는 이미 알린 단계를 반복하지 않으며, 새 청구 기간이나 사용량 보정 시 알림 이력을 초기화합니다. 테스트 알림 이력은 실제 이력과 분리됩니다. iPad 알림 설정과 집중 모드에 따라 배너가 표시되지 않을 수 있습니다.

`Rapid Usage Warning`은 최근 두 측정 사이에 300 MB 이상 증가하고 경고 기준 이상일 때 급증 안내를 표시합니다. 실시간 전송 속도를 측정하는 기능은 아닙니다.

## 데이터와 개인정보

설정, 누적 사용량, 최근 100개 측정 기록은 앱 내부에 저장합니다. 외부 서버로 전송하는 코드나 분석 SDK는 없으며, 진단 화면의 IP 주소는 저장하지 않습니다. 앱을 삭제하면 로컬 기록도 삭제됩니다.

VPN·프록시·패킷 가로채기를 사용하지 않습니다. DataGuard 자체가 셀룰러 설정을 변경하는 기능도 없으며, 실제 끄기 동작은 연결한 Apple 단축어가 담당합니다.

## 개발 및 검증

핵심 계산 로직은 macOS에서 Swift Package 테스트로 확인할 수 있습니다.

```sh
swift test
```

서명 없는 컴파일 검증:

```sh
./Scripts/build.sh iphoneos Release
./Scripts/build.sh iphonesimulator Debug
```

빌드 로그는 `Validation/`에 생성되며 Git 추적에서 제외됩니다. 실제 iPad 설치에는 Xcode에서 본인의 Team을 선택해야 합니다.

측정에는 `getifaddrs`로 읽은 인터페이스별 수신·송신 카운터를 사용합니다. 카운터가 32비트이므로 각 방향에서 약 4.29 GB마다 순환할 수 있습니다. 초기화와 순환을 항상 구분할 수 없고, 측정 사이에 발생한 여러 번의 순환이나 인터페이스 재생성은 복원하지 못할 수 있습니다. 앱에 저장하는 UInt64 값은 이 원본 카운터의 제약을 없애지 않습니다.

| 경로 | 역할 |
|---|---|
| `DataGuard/Core/` | 인터페이스 측정, 누적 계산, 설정·파일 저장, 알림 정책 |
| `DataGuard/Views/` | 대시보드, 인터페이스 진단, 설정 화면 |
| `DataGuard/Intents/` | 단축어 동작과 결과 타입 |
| `DataGuard/AppModel.swift` | 화면과 단축어의 공통 측정·저장 흐름 |
| `DataGuard/NotificationService.swift` | 로컬 알림 권한 및 전송 |
| `Config/` | 앱 구성 파일 |
| `Tests/` | 핵심 로직 테스트 |
| `Scripts/`, `Design/` | 빌드·아이콘 생성 도구와 디자인 원본 |
| `Validation/` | 개발 당시의 검증 기록과 화면 자료 |
